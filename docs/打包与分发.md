# 打包与分发

本文针对 macOS 桌面应用，不是 Mac App Store 发布流程。当前默认脚本生成本机架构、临时签名的测试包；正式向普通用户分发，应使用 Developer ID 签名与 Apple 公证。

## 一、准备构建环境

在 Mac 上安装 Swift 6+ 和匹配的 Command Line Tools 或 Xcode，确认：

```sh
swift --version
xcode-select -p
xcrun --find codesign
```

需要完整 Xcode 提供的功能时，应先按 Apple 的说明完成 Xcode 安装和开发工具选择；不要为了打包随意切换现有开发环境。

从仓库根目录操作：

```sh
git clone https://github.com/YubaKevin/claude-sentinel.git
cd claude-sentinel
```

## 二、一条命令生成测试 ZIP

```sh
./scripts/package.sh
```

Apple 芯片 Mac 上的默认产物：

```text
output/ClaudeSentinel.app
output/ClaudeSentinel-0.1.0-macos-arm64-adhoc.zip
output/ClaudeSentinel-0.1.0-macos-arm64-adhoc.zip.sha256
```

脚本会构建 Release、生成10张16–1024像素的图标图片并转换为 `AppIcon.icns`、写入应用清单、临时签名并校验签名，然后用 `ditto` 保留应用目录结构和执行权限打包，最后生成 SHA-256 校验文件。只构建应用而不压缩可运行 `./scripts/build.sh`。

版本号与构建号可以指定；不要覆盖已发布的同版本附件，应递增版本号：

```sh
VERSION=0.1.1 BUILD_NUMBER=2 ./scripts/package.sh
```

可以在本机验证：

```sh
output/ClaudeSentinel.app/Contents/MacOS/ClaudeSentinel --self-test
open output/ClaudeSentinel.app
cd output
shasum -a 256 -c ClaudeSentinel-0.1.0-macos-arm64-adhoc.zip.sha256
```

`--self-test` 不访问真实代理或账号；`--probe` 会执行真实网络检查并输出可能含 IP 的结果，不要把输出当作可公开测试日志。

### 架构与兼容性

脚本读取最终二进制的实际架构命名 ZIP：Apple 芯片通常为 `arm64`，Intel 为 `x86_64`。当前脚本只构建本机默认架构，不自动生成 Universal 包。

- 发给 Apple 芯片用户：在 Apple 芯片 Mac 构建并测试 `arm64` 包。
- 发给 Intel 用户：在 Intel Mac、使用兼容的 Swift 工具链构建并测试 `x86_64` 包。
- 如以后采用双架构构建，可以按 Apple 的 Universal Binary 流程合并，但必须在两个架构上验证。不能仅改 ZIP 文件名冒充另一个架构。

构建目标为 macOS 14+。发布前还应在实际支持的系统版本验证；目前未在 Intel 与最低目标系统上做实机验证。Apple 的背景说明：[Building a universal macOS binary](https://developer.apple.com/documentation/apple-silicon/building-a-universal-macos-binary)。

## 带像素背景与拖拽引导的 DMG

构建者需要 Python 3，依赖只安装到项目的 `.build/` 虚拟环境，不纳入 Git：

```sh
python3 -m venv .build/dmg-tools
.build/dmg-tools/bin/pip install -r scripts/requirements-dmg.txt
./scripts/package-dmg.sh
```

脚本先执行应用允许列表与签名检查，再从空白暂存目录创建 HFS+ 安装盘。安装盘只放入应用、指向 `/Applications` 的符号链接、太空站背景、卷图标和新建的 Finder 布局文件；不使用个人桌面的 `.DS_Store`，背景引用也从安装盘内部生成。

布局固定为720×480点，两个图标之间有像素箭头。只读压缩 DMG 与 SHA-256 文件位于 `output/`。默认命名为 `ClaudeSentinel-0.1.0-macos-arm64-adhoc.dmg`，依然是未公证测试包。

接收者打开 DMG 后，将小猫拖到 Applications，从“应用程序”打开，再推出安装盘。无需安装 Python 或构建工具。

构建期间会临时挂载 `/Volumes/Claude Sentinel`，结束后自动卸载；如果该卷已存在，会要求先推出自己的同名安装盘，避免误操作。脚本使用 `hdiutil`；部分较新系统可能提示该命令的创建功能已弃用，当前已验证仍可完成打包。

如果需要正式分发 DMG，完成 Developer ID 应用签名后还应按 Apple 的流程对最终 DMG 签名、公证并附加票据。下文示例演示的是应用 ZIP 公证，不会自动给 DMG 做公证。本仓库的首个 Release 明确标记为未公证预览测试版。

## 三、正式分发：Developer ID 签名与公证

`adhoc` 是临时签名，不是 Apple Developer ID 签名，也不是公证。它适合本地开发测试，不能承诺下载后直接通过 Gatekeeper。

正式分发需要可用的 Apple Developer ID Application 证书及对应私钥，以及公证服务的认证方式。以下均为占位示例，不包含真实身份或凭据。Developer ID 证书本身会展示开发者身份/团队信息，不能把它当作匿名签名。

### 1. 用 Developer ID 构建并打包

证书应已安装在自己的登录钥匙串中：

```sh
SIGN_IDENTITY='Developer ID Application: YOUR_NAME (TEAM_ID)' \
VERSION=0.1.0 BUILD_NUMBER=1 ./scripts/package.sh
```

脚本对应用启用 hardened runtime 和安全时间戳。输出包名末尾为 `developer-id.zip`，**此时只是已签名，还未公证**。Apple 芯片示例：

```text
output/ClaudeSentinel-0.1.0-macos-arm64-developer-id.zip
```

### 2. 配置公证认证并提交

按工具交互提示在自己的 Mac 设置钥匙串凭据，或使用 Apple 文档支持的 App Store Connect API key 方式。不要把 Apple ID 密码、应用专用密码、证书私钥或 `.p8` 文件写入仓库：

```sh
xcrun notarytool store-credentials 'claude-sentinel-notary'
xcrun notarytool submit \
  output/ClaudeSentinel-0.1.0-macos-arm64-developer-id.zip \
  --keychain-profile 'claude-sentinel-notary' --wait
```

必须确认结果为 `Accepted`。若失败，按提交 ID 查询日志并修复后重新提交；单纯上传成功或“正在处理”不算公证通过。

### 3. 附加票据并重新打包

ZIP 本身不能附加票据，应对里面的 `.app` 执行 staple，然后重新生成分发 ZIP：

```sh
xcrun stapler staple output/ClaudeSentinel.app
xcrun stapler validate output/ClaudeSentinel.app
codesign --verify --strict --verbose=2 output/ClaudeSentinel.app
spctl --assess --type execute --verbose=2 output/ClaudeSentinel.app

ditto -c -k --keepParent --norsrc --noextattr \
  output/ClaudeSentinel.app \
  output/ClaudeSentinel-0.1.0-macos-arm64-notarized.zip

(cd output && shasum -a 256 \
  ClaudeSentinel-0.1.0-macos-arm64-notarized.zip \
  > ClaudeSentinel-0.1.0-macos-arm64-notarized.zip.sha256)
```

版本号和架构需与实际产物一致。Staple 后不要再运行构建脚本覆盖应用，也不要修改已签名包的内容；否则需要重新签名、公证与打包。

Apple 官方流程：[Notarizing macOS software before distribution](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)、[Customizing the notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)。

本项目当前没有自动公证或自动发布功能；上述签名/公证步骤需要发布者自己具备相应证书和账号并执行，不代表仓库中的测试包已通过公证。

## 四、交给别人或发布到 GitHub Releases

交付的是与对方 CPU 匹配、完成所需签名公证的 **ZIP 与 `.sha256`**，并附上[使用说明](使用说明.md)。接收方解压应用并拖入“应用程序”，无需安装构建工具，但仍需要自己的代理配置。

不要直接压缩整个项目目录发送，也不要把以下内容加入附件：

- `.build/`、调试符号、构建日志、本机路径信息。
- `~/Library/Application Support/ClaudeSentinel/` 中的偏好和历史。
- Clash 配置、订阅链接、代理密码、OAuth token、证书私钥或钥匙串导出。
- 含真实出口 IP 或账号信息的截图。

打包脚本只允许当前应用所需的四类文件（应用清单、可执行文件、应用图标和签名）进入包，并拒绝符号链接与意外文件；如果以后增加其他资源，需要先审查内容再扩展允许列表。`output/` 和本机偏好文件已被 Git 忽略。

在 GitHub 仓库的 Releases 页面创建版本，填写版本号、适用架构、最低系统、是否已公证及已知限制，再上传最终 ZIP 和校验文件。不要把未公证包标成已公证版本，也不要把源码下载入口当作应用安装包。

## 五、发布前验收

在没有原作者配置的另一台测试 Mac 验证：

1. 解压后目录结构、执行权限和签名完整；校验值匹配。
2. 应用能启动，菜单栏有小猫；关闭窗口后继续运行，退出后停止监控。
3. 使用对方自己的代理端口，能得到真实连通结果；缺少 Mihomo、DNS 或 CLI 时正确显示未知/提醒。
4. 等待三次自动检查，正常时绿球；可控测试网络失败后红球、恢复后重新确认。不要为测试修改生产代理或暴露凭据。
5. 暂停、休眠、唤醒、网络切换和“减少动态效果”表现正确。
6. 安装包内没有原作者的偏好、检测记录、截图或凭据。

当前脚本自动验证签名与文件允许列表；真实设备兼容性、Gatekeeper 与公证需要对应环境另行验收。
