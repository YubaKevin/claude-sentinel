# 使用说明

## 支持哪些电脑

当前仅支持 **macOS**。程序使用 SwiftUI、AppKit 和 macOS 网络接口，不能直接运行在 Windows、Linux、iPhone 或 Android 上。

| 项目 | 要求 |
| --- | --- |
| 系统 | 构建目标为 macOS 14 Sonoma 或更高版本 |
| Apple 芯片 Mac（M 系列） | 使用 `arm64` 包 |
| Intel Mac | 使用 `x86_64` 包，需另行在 Intel Mac 构建 |
| 已打包应用的使用者 | 不需要安装 Swift、Xcode、Homebrew 或 Python |
| 从源码构建的人 | 需要 macOS、Swift 6+ 和对应 Command Line Tools / Xcode |

当前本机验证的是 Apple 芯片版。Intel 版及最低系统 macOS 14 尚未实机验证；最低构建目标不等于已经测试了所有系统版本。目前没有 Windows/Linux 版，也没有自动生成 Universal 版的脚本。

## 安装与启动

1. 获取与自己的 CPU 匹配的 ZIP。仅在仓库实际发布 Release 附件后才有可直接下载的安装包；GitHub 的“Download ZIP”下载的是源码。
2. 解压得到 `ClaudeSentinel.app`，将它拖入“应用程序”文件夹。
3. 打开应用，首次进入详情窗口，菜单栏出现猫咪和线球。应用文件本身使用深蓝底的小猫线球图标；这个固定图标不表示实时网络状态。
4. 关闭详情窗口后程序仍会运行；点击菜单栏猫咪可以重新查看报告，在弹窗底部退出。

正式分发版本应采用 Developer ID 签名并通过 Apple 公证。文件名带 `adhoc` 的是本地测试包，macOS 可能阻止从互联网下载的此类应用。不要因此关闭系统安全保护；可以选择在自己的 Mac 上从源码构建，或等待正式签名公证版本。打包与公证流程见[打包与分发](打包与分发.md)。

本程序不会自动注册开机启动，也不会自动升级。

## 启动前准备代理

本工具是网络观察器，**不会提供代理节点、订阅或住宅 IP，也不会自动帮你开启代理**。使用者需要自己的代理服务。

先打开自己的代理客户端，再到小哨兵“设置”里调整：

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| HTTP 代理 | `http://127.0.0.1:7890` | 改为自己的本机 HTTP/mixed 代理端口，不填远端节点密码 |
| Mihomo Socket | `/tmp/verge/verge-mihomo.sock` | 仅支持本地 Unix Socket；其他控制方式可能无法读取链路 |
| 本地 DNS 端口 | `1053` | 需有 DNS 服务监听在 `127.0.0.1` 的对应端口 |
| 连通监控 | 30 秒 | 可选 15/30/60 秒 |
| 完整检测 | 5 分钟 | 可按需调整 |

当前优先适配 Clash Verge Rev / Mihomo。详细适配边界：

- 前置节点的读取目前从名为 `前置节点自动切换` 的代理组开始，递归跟随当前选择。自己的组名不同可能显示“未识别”，这不等同于代理失效；组名暂时不能在界面里设置。
- DNS 上游配置固定从 Clash Verge Rev 的标准 Application Support 目录读取。只有上游均明确标注 `#住宅代理链` 时，程序才会显示已配置代理解析；其他命名可能显示未知。不要为了变绿盲目修改代理配置。
- 没有 Mihomo 或对应 DNS 监听时，部分项目会显示未知或提醒。HTTP 代理可达性仍可以单独检查。
- Claude Code CLI 是可选项。仅在 `~/.local/bin/claude` 存在时检查登录记录；没有 CLI 不影响基础网络监控。网页登录、桌面登录和 CLI 登录不是同一个检测项。

设置后点击“保存设置”，程序会重新检查，不需要输入订阅地址、账号密码或 token。

## 线球与实时监控

| 线球 | 表示什么 |
| --- | --- |
| 绿色 | 最近至少三次连通检查成功，出口一致，响应波动未超过阈值，完整检查未发现明确 DNS/UDP 异常 |
| 红色 | 连接失败、响应明显波动、出口变化，或 DNS/UDP 存在明确异常；点开查看具体原因 |
| 灰色 | 检查中、样本不足、结果过期、暂停或休眠，不能断言正常 |

默认启动后约一分钟以上才可能积累三次正常结果，并开始播放拨线球动画。不要把刚启动时的灰色当作故障。

每约30秒并行检查 API 连通与 Cloudflare 所见出口；完整 DNS、UDP、IPv6、官方状态与 CLI 登录记录默认每五分钟检查。系统网络路径类型/状态变化和 Mac 唤醒后会补查，睡眠期间停止检测。默认故障发现可能需要约30–45秒，完整检查覆盖的问题可能需要等到下一轮完整检测。

如果启用 macOS“减少动态效果”，猫咪使用静态图标，线球仍会更新颜色。

## 结果如何理解

- API 可达只证明网络能到服务端，不证明账号可用、模型权限正常或 OAuth 没有过期。匿名检查不会调用模型或消耗 Claude token。
- 出口是 Cloudflare 观测到的地址，不是直接测得的 Anthropic 所见地址。
- STUN 是系统 UDP 路由的观测，不能替代浏览器 WebRTC 检测；DNS 配置核对也不是完整的浏览器权威 DNS 泄露测试。
- 绿色仅表示已覆盖项目的短时网络观测正常，仍可能存在未知检测项。不预测 KYC、封号或服务地区合规性。
- 当前不会拦截 Claude 应用启动或每条消息，也没有配置 Claude Code 启动 Hook；这些功能尚未实现。

## 本机数据与卸载

设置和最近96条完整检测摘要保存在：

```text
~/Library/Application Support/ClaudeSentinel/
```

轻量连通记录只保留最近六条于内存。历史可能包含出口 IP、节点名称、地区、时区和诊断结果。“隐藏 IP”只遮盖界面与复制报告，不会删除磁盘记录。

程序会联系 Cloudflare、Anthropic、Google STUN，以及可选 IPinfo；不会上传检测历史，不提取代理密码或登录 token，不修改代理、网络接口、系统时区或 zshrc。

卸载时先退出应用，再将 `.app` 移到废纸篓；如果也不需要历史，可自行将上述专用数据文件夹移到废纸篓。不要把这个数据目录发送给别人，分享报告前也应先隐藏 IP 并检查内容。
